# 회고 저장 장애 수정·복구 계획

사용자가 2026-10-22에 데이터 소스 지정 방식 수정, 운영 배포, 10/15 이후 누락 회고 복구, 향후 실패 알림을 승인했다. 이 문서는 한국어 원본이다.

## 요구 사항과 결정

- 회고 DB의 데이터 소스 목록과 스키마를 읽기 전용으로 확인하고 기존 회고가 들어 있는 소스 ID를 명시적으로 설정한다. 임의로 첫 번째 소스를 고르지 않는다.
- 회고 경로만 Notion API 2025-09-03의 데이터 소스 조회 및 페이지 생성으로 변경한다. 다른 Notion 연동의 SDK는 유지한다.
- 박영민의 posted/manual-edit 데일리 중 ‘오늘의 배움 또는 남길 말’ 원문만 저장한다. 자동 게시, 주간, 다른 사람은 제외한다.
- 2026-10-15부터 실행 시점의 전날까지 날짜별 조회한다. 기존 날짜·제목·본문이 일치하면 재사용하고, 충돌 또는 복수 항목이면 덮어쓰지 않고 오류로 남긴다.
- 기존 날짜별 생성 의도 잠금을 유지한다. 응답 유실 후 기존 항목으로 복구하며, 생성 여부가 불명확하면 두 번째 POST를 보내지 않는다. 과거 복구와 현재 scheduler도 이 잠금을 공유한다.
- 복구는 먼저 dry-run으로 대상과 충돌을 확인한다. 원문은 운영 로그에 출력하지 않는다. 완료 후 같은 범위를 다시 조회해 추가 생성이 없음을 검증한다.
- 실패 알림은 기존 운영용 Discord mgmt 채널을 사용한다. 날짜별 첫 실패와 6시간 이상 지속된 실패를 알리고, 성공한 알림 상태는 SQLite에 보존해 재시작 후 반복 발송을 억제한다. 알림 실패는 저장 재시도를 막지 않는다. 알림 본문에는 회고 원문·토큰·API 응답 전문을 포함하지 않는다.
- 기존 09:00 KST 일정과 매분 재시도는 유지한다. 범위 복구는 명시적 CLI/workflow로만 수행한다.
- 배포는 기존 백업·rollback 경로로 notion-cron 서비스만 교체한다. 데이터베이스 삭제나 기존 Notion 항목 수정은 하지 않는다.

## 실행 순서와 합격 조건

1. `src/services/daily-reflection-service.ts`, 신규 Notion API 어댑터: 실제 HTTP 모의 서버로 데이터 소스 경로/버전/부모 ID를 확인하는 테스트가 기존 코드에서 실패하는 것을 확인하고 수정한다. 기존 중복·응답 유실·본문 충돌 테스트도 통과해야 한다.
2. 신규 알림 서비스와 `src/scheduler.ts`: 실패 시 알림, 매분 반복 억제, 6시간 후 재알림, 재시작 보존, 알림 전송 실패 격리를 테스트한다.
3. 신규 복구 CLI와 Oracle workflow: 소스 조회, 범위/날짜 검증, dry-run, 실제 복구, 다시 실행 시 기존 항목 재사용을 검증한다.
4. 전체 기존 테스트와 TypeScript 빌드를 통과시키고 diff를 검토한다. 커밋·PR에 변경과 검증을 기록한다.
5. 운영 소스 ID 확인 및 dry-run 후 배포한다. 10/15 이후 수정 제출 원본과 Notion 결과를 대조하고 복구 후 재검증한다. Discord 알림은 검증용임을 표시한 메시지로 실제 전송·조회 여부를 확인한다.

## 진행 기록

- 조사: DB가 두 데이터 소스를 가지며 구형 API 400 오류 발생. 수정 제출 원본은 SQLite에 남아 있다.
- 구현: 전체 18개 로컬 테스트와 빌드 통과. 독립 코드 리뷰의 알림 무한 대기 지적을 15초 timeout 및 회귀 테스트로 수정했다.
- 운영 소스 확인: `3fabd55c-4778-80bb-ac97-000b65c0fda9`가 10/14 기존 회고를 가진 영민 회고록 소스다. 다른 소스는 Name 속성만 가진 빈 소스다.
- 첫 배포 검증에서 Docker 사전검사가 SSH의 스트리밍 표준 입력을 소비해 서버 교체를 건너뛰는 문제를 발견했다. 실제 스트리밍 Bash 회귀 테스트로 재현하고 모든 compose 사전검사에 stdin 차단을 추가한다. 운영 runtime 모듈 검사와 SSH 밖 health 필드 검사도 추가해 거짓 성공을 막는다. 첫 복구 dry-run은 CLI가 구서버에 없어 실패했으며 Notion 쓰기는 실행하지 않았다.
