# 전날 데일리 회고 서버 자동 저장 구현 계획

요청된 실행 방식: 기존 Oracle 서버의 스케줄러에서 매일 한국 시간 오전 9시 이후 첫 tick에 전날 업무일의 회고만 저장한다. 사용자 지시로 실행 방식과 시간, 제외 조건이 확정되었다.

## 동작과 범위

- SQLite 게시 기록에서 박영민, 데일리, posted, manual-edit만 선택한다. 짧은 업무일 표기와 생성 시각 범위를 함께 확인하여 연도를 구분한다.
- ‘오늘의 배움 또는 남길 말’만 원문 문단으로 저장한다. 자동 게시, 그대로 게시, 헬스체크만 입력, 주간 및 다른 날짜는 제외한다.
- 대상 DB는 영민 회고록(3fabd55c-4778-803a-be0a-d82bea2341a6). 이름은 YYYYMMDD(한글요일), 날짜는 업무일 종일 날짜다.
- 날짜별 기존 페이지를 페이지네이션하여 중복을 막는다. 기존 본문/제목이 다르면 덮어쓰지 않고 작업 실패로 기록한다. 같은 날짜에 서로 다른 수정본이 있어도 실패 처리한다.
- Notion 생성 전에 SQLite에 날짜별 생성 의도를 원자적으로 저장한다. 응답 유실/프로세스 중단 후에는 Notion을 재조회하고, 페이지가 계속 없으면 자동으로 두 번째 생성 요청을 보내지 않는다. 관리자 확인 후 해당 의도 키를 지워 복구할 수 있다.
- 생성/기존 항목의 제목, 날짜, 본문을 다시 확인한 뒤 성공 마커를 남긴다. 다른 작업 실패가 회고 작업을 막지 않고, 회고 실패도 다른 작업에 영향을 주지 않는다.
- 서버가 9시 이후 재시작하면 그날 대상만 복구한다. 성공 또는 수정본 없음으로 완료된 날짜는 반복하지 않는다. 과거 누락분을 일괄 생성하지 않는다.
- Codex의 30분 heartbeat는 삭제한다. 기존 회고의 요일 포함 제목을 유지한다. 별도 Discord 알림이나 LLM 호출은 추가하지 않는다.

## 운영 확인

현재 토큰과 DB 스키마 접근은 앞선 저장 작업에서 검증했다. 운영 서버 진단은 기존 workflow의 DISCOVER로 확인한다. 이번 요청은 기존 서버에 동작하도록 변경하는 범위를 승인한다. 배포는 notion-cron 컨테이너만 교체하고 다른 서비스/데이터는 변경하지 않는다.
