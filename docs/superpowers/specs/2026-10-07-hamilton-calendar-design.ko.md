# Hamilton 업무 캘린더 전날 생성 및 필터 보정

## 요구사항
- 한국 시간 매주 화·수·목·금·토 오후 1시에 다음 날 수·목·금·토·일의 Hamilton 업무 캘린더 페이지를 하나씩 생성한다. 예: 화요일 13시에 수요일 페이지 생성.
- 업무 캘린더에 이미 존재하는 Hamilton 템플릿을 사용한다.
- 제목은 박영민 페이지와 동일한 형식으로 대상 날짜를 표시하고, `일정`도 대상 날짜, `사람`은 Hamilton으로 설정한다. 템플릿의 `@Today`가 생성일로 남지 않도록 제목을 명시적으로 설정한다.
- 생성 작업 안에서 링크드뷰의 날짜 조건 `today`를 대상 날짜로 고정하고 검증한다.
- 기존 박영민 보정과 함께 Hamilton 기존 페이지도 보정 대상으로 포함한다.

## 확인된 환경
- 업무 캘린더 데이터 소스: `26abd55c-4778-80a6-b4c3-000b1976e9d8`.
- Hamilton 템플릿: `3f2bd55c-4778-8043-9ed0-d337f8b50734`.
- Hamilton 사람 ID: `3f0d872b-594c-81a9-a34d-00024bd9314d`.
- 두 사람 템플릿 제목은 동일하므로 템플릿 이름만으로 선택하지 않는다. 확인된 ID와 사람 속성을 검증한다.
- Hamilton 첫 번째 콜아웃 내부 `오늘의 업무` 뷰에는 현재 날짜 필터가 없다. 콜아웃 밖 `Archy 업무` 뷰에는 `미완료 OR (완료 AND 완료일=today)` 조건이 있다.
- Notion 템플릿 적용은 비동기다. 생성과 필터 수정은 원자적이지 않으며, 생성 직후 잠시 빈 본문 또는 `today` 조건이 보일 수 있다.

## 선택지와 결정
1. 권장: 기존 Oracle 상주 scheduler에 생성 작업을 추가한다. 한국 시간 13시 이후 해당 날짜에 실행되지 않은 작업을 실행하고 재시작 시에도 같은 날 복구한다. 기존 실행 기록 체계를 활용한다.
2. GitHub Actions에 화~토 13시 예약을 추가한다. 구현은 단순하지만 예약 실행 지연이 있어 정확한 시각 실행에는 덜 적합하다.
- 권장안을 사용한다. 전날 설계의 수~일 오전 8시 15분 추가 실행은 폐기한다. 박영민의 기존 평일 오전 3시 보정은 유지한다.

## 생성 및 복구 흐름
1. 한국 시간 실행일과 다음 날 대상 날짜를 계산한다. 자동 생성은 화~토에만 실행한다.
2. 대상 날짜의 Hamilton 페이지를 사람 ID와 일정으로 조회한다. 이미 한 개 있으면 새로 만들지 않고 보정 및 검증을 수행한다. 여러 개면 임의 선택하지 않고 오류를 기록한다.
3. 없으면 확인된 Hamilton 템플릿으로 페이지를 생성하고 제목·일정·사람을 설정한다. 템플릿 원본은 수정하지 않는다.
4. 템플릿의 예상 블록과 업무 DB 링크드뷰가 나타날 때까지 제한된 재시도로 기다린다. 빈 본문이나 미완성 뷰를 성공으로 처리하지 않는다.
5. 새로 생성하거나 생성 작업으로 복구하는 Hamilton 페이지에서는 콜아웃 밖을 포함한 모든 내부 업무 DB 링크드뷰의 `완료일=today` 조건을 대상 날짜로 바꾼다. 기존 논리 구조와 다른 필터는 유지하며, 날짜 조건이 없는 뷰에 임의로 조건을 추가하지 않는다.
6. 재조회로 대상 날짜를 검증한 뒤에만 실행 성공을 기록한다. 실패하면 다음 scheduler tick에서 기존 페이지를 재사용하여 복구한다. 동시 실행을 막고 재실행 시 중복 생성을 방지한다. 생성 요청 응답 유실 시 재조회 후 복구하며 무조건 POST를 반복하지 않는다.
7. 기존 독립 보정 작업은 박영민 또는 Hamilton 사람 조건을 OR로 조회한다. 이 작업의 첫 번째 콜아웃 범위와 고정 날짜 보존 정책은 유지한다.

## 운영 전환
- Hamilton의 Notion 자체 반복 생성이 활성화되어 있다면 배포 전 해제해야 한다. 두 생성기를 함께 켜면 중복 페이지가 생길 수 있다.
- 반복 생성 설정의 현재 활성 여부와 변경 가능 여부는 확인이 필요하다. API로 변경할 수 없다면 UI 또는 사용자 설정으로 해제한다. 해제 여부가 확인되기 전 새 자동 생성기를 활성화하지 않는다.
- 설정 예시, Oracle 운영 문서와 README를 동기화한다. 수동 실행 및 dry-run을 제공한다.
- 첫 활성화 당일 13시가 지났으면 그날 화~토에 해당할 때 다음 날 한 페이지를 준비한다. 지나간 날짜를 일괄 생성하지 않는다.

## 검증과 수용 기준
- 화~토 13시 한국 시간 → 다음 날 수~일 날짜 매핑, 13시 이전 미실행, 일·월 미생성, 월말·연말 날짜 계산을 검증한다.
- 템플릿과 사람 ID 검증, 제목·일정·사람 설정을 확인한다.
- 템플릿 비동기 적용 지연, 실패 후 재실행, 이미 존재하는 페이지 및 중복 페이지를 검증한다.
- 생성된 Hamilton 페이지의 콜아웃 밖 Archy 업무 뷰에서도 `today`가 대상 날짜로 바뀌며 기존 OR/AND 의미와 다른 필터가 유지된다.
- 박영민과 Hamilton 조회 조건 및 기존 보정 회귀 테스트, TypeScript 빌드가 통과한다.
- 실제 쓰기 전 dry-run으로 템플릿·대상 날짜·중복 여부를 확인한다. 실제 생성 후 속성과 필터를 재조회하여 검증한다.
